# Google Cloud Platform (GCP) & Firebase Architecture

## Infrastructure Choice
Fusion Neural relies on **Google Cloud Firestore** as its primary real-time database, operating within the GCP Project `logical-pathway-495218-u5`.

## Architecture Paradigm: REST over gRPC
To bypass complex dependency conflicts (like `grpcio` and `firebase-admin` issues on Windows), the backend utilizes a custom `FirestoreRESTClient`. This client communicates directly with the Firestore REST API using `google.auth.transport.requests` and standard HTTP `PATCH/POST` requests.

## Authentication
Authentication is handled strictly server-side using a GCP Service Account key located at `backend/gcp-credentials.json`. 

## Core Database Collections
The web platform's real-time reactivity is driven by these core Firestore collections:
- `agent_budgets`: Financial tracking for AI agent operations.
- `pending_approvals`: The Human-in-the-Loop gateway. Holds AI-generated JSON payloads, code modifications, and drafts awaiting Manager approval.
- `ai_tickets`: Work items assigned to AI agents.
- `run_transcripts`: Deep dive logs into the internal "Thought Process" of the AIs.
- `activity_logs`: Global network event logging.
- `neural_tasks`: The main Kanban board tasks generated by the Orchestrator.

## Deployment Strategy
While currently running locally via Vite + FastAPI, the ultimate deployment target for the static frontend is Firebase Hosting or Vercel, with the Python backend containerized on Google Cloud Run to maintain minimal latency with Firestore.
